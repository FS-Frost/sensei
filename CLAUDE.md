# CLAUDE.md

Japanese-reading tutor for a Spanish speaker. **Static site (GitHub Pages)**: SvelteKit 3 SPA (`adapter-static`, `ssr = false`) + Svelte 5 (runes) + TS; the former server runs **in a Dedicated Worker** in the browser: SQLite WASM (`@sqlite.org/sqlite-wasm`, VFS `opfs-sahpool`) + Drizzle, Gemini via `@google/genai` with the user's key. Tooling/tests run on **Bun** (`bun:sqlite`). UI and all learner-facing text in Spanish; Japanese never in romaji.

## Commands

- `bun run build:dict [--variants common,full] [--no-examples]` — builds the publishable dictionary DB into `static/dict/` (gzip, parts < 100 MB, `manifest.json` with content-hash version). Needed before `dev`/`build`.
- `bun run dev` — Vite dev server
- `bun test` — tests in `tests/` (Bun, `bun:sqlite` in memory; `tests/wasm-client.test.ts` runs the browser adapter on real SQLite WASM)
- `bun run check` — svelte-check; keep at 0 errors / 0 warnings
- `bun run build` — static site in `build/`; `BASE_PATH=/<repo>` for Pages (Git Bash: prefix `MSYS_NO_PATHCONV=1` or it mangles `/repo`). CI copies `404.html` → `index.html`.
- `bun run export:local [db] [zip]` — migrate a server-era `data/sensei.db` to an import .zip
- `bun run db:generate` — after editing `src/lib/server/db/schema.ts`; migrations in `drizzle/` are bundled into the Worker (`import.meta.glob` + `_journal.json`, same hashes as Drizzle's migrator) and applied on open
- `bun run pregen:import <export.zip> [--dry]` — merges content generated in the app (an export with «Contenido generado») into `content/pregen.json` (`pregenFromSnapshot` + `mergePregen` in `data/pregen.ts`: only fills missing keys, skips `u:` vocab, excludes personal mnemonics, tutor-regenerated ones and leech kanji).
- `GEMINI_API_KEY=… bun run pregen [--kanji N] [--dry]` — pregenerates mnemonics/glosses/sentences/similar tips for the first N kanji into `content/pregen.json` (versioned; incremental and resumable; uses `GEMINI_MODEL_PRO/FLASH` from `.env` if set). `build:dict` applies it with origin `pregen`.
- Deploy: `.github/workflows/main.yml` (check, test, build:dict common+full, build, push `build/` to `gh-pages`). Bun pinned (1.3.14), actions on Node 24 versions.
- Local preview caveat: `bun run preview` caches the file index at startup — restart it after each `bun run build`. Headless Edge `--screenshot/--dump-dom` freezes time (the Worker never settles): drive it through `--remote-debugging-port` instead.

## SvelteKit 3 specifics (differ from Kit 2 knowledge)

- No `svelte.config.js`: Kit options go in the `sveltekit({...})` plugin in `vite.config.ts`.
- Alias is `#lib/*` (package.json `imports`), **imports need file extensions** (`#lib/server/db/index.ts`).
- `$app/state` (no stores), `refreshAll` (not `invalidateAll`).
- Use `Response.json()`, not `json()`.
- `$app/paths` has no `base` in Kit 3: use `#lib/client/base.ts` (`import.meta.env.BASE_URL`).
- `tsconfig.json` `types` must include `$app/types`.
- TypeScript pinned to 6.x (TS 7 has no JS API; svelte-check breaks).

## Static-site architecture («server in a Worker»)

- `src/lib/worker/backend.worker.ts` — opens SQLite (OPFS), installs/updates the dictionary, serves `/api/*` with the old handlers (`src/lib/server/api/**/+server.ts`, routed by `server/router.ts`) and page `load`s (`src/lib/server/loads/*.ts`). Web Lock `sensei-db`: a 2nd tab gets state `locked`. Starts the hourly backup scheduler.
- `src/lib/client/backend.svelte.ts` — creates the Worker, **patches `window.fetch`** so same-origin `/api/*` (with or without base) goes to the Worker (streams chunk by chunk, so the tutor SSE works unchanged); `serverLoad(route, params, url)` for universal `+page.ts`/`+layout.ts`; `backend.value` = BackendState (`starting|needs-dict|installing|ready|locked|unsupported|error`). The layout shows `Setup.svelte` until `ready` and calls `refreshAll` when it becomes ready.
- Loads run in the Worker: use `redirect`/`error` from `#lib/server/router.ts` (Kit's need `window`). Type `load` params with `ServerLoadEvent`, never annotate the return (it erases `PageData`).
- `<img src="/api/…">` / `<a href="/api/…">` bypass the Worker: fetch + blob URL (`KanjiDetail` strokes, `downloadFrom` for export/backups).
- Base path: `client/basePath.ts` MutationObserver prefixes every `<a href="/…">` with the base; `goto` from `#lib/client/nav.ts`. Compare routes with `page.url.pathname.slice(base.length)`.
- `server/db/index.ts` — platform-neutral: `db` is a Proxy over the instance set with `setDb()`; `DB` includes `$client.query` (cached statements, used by `text/analyze.ts`). `db/bun.ts` = `openDb()` for tests/scripts; `db/wasm.ts` = OPFS pool + bundled migrations; `db/wasm-client.ts` = `BunLikeClient` (bun:sqlite-shaped wrapper over oo1 so `drizzle-orm/bun-sqlite` works).
- `server/data/dictionary.ts` — download parts (`?v=<manifest.version>`: part names repeat across versions, so the HTTP cache would serve the old one) → `DecompressionStream('gzip')` → `importDbFile`. Update/switch variant = `pre-update` backup → snapshot user data + `_` internals → new DB → `applySnapshot` + restore internals. `_dictVersion`/`_dictVariant` internals.
- `vite.config.ts` aliases: `node:async_hooks` → `shims/async_hooks.ts` (stack-based AsyncLocalStorage), `@open-spaced-repetition/binding` → `shims/fsrs-binding.ts` (fsrs-browser WASM). Bun/tests use the real modules. No `node:*`/`Bun.*` in code reachable from the Worker (use `crypto.randomUUID`, Cache API, OPFS).
- Backups: `data/store.ts` BlobStore (OPFS folder `backups/` in the browser; `store-fs.ts` for tests). `backups.ts` functions are async and take a store.
- `server/config.ts` — no `.env`: Gemini key stored as internal setting `_geminiApiKey` (never exported), loaded by the Worker, set via `POST/DELETE /api/gemini-key` (validated with `listModels`). Optional hard budget stop (`budgetHardStop` + `assertBudget` before every call).
- No PIN/auth any more (each browser only sees its own data).
- **Device sync** (`/sincronizar`, plan `docs/sync-qr.md`): pair by sound (ggwave) or QR/paste, transfer over the **LAN** with WebRTC (no ICE servers, host candidates only). WebRTC can't run in the Worker, so the page holds the connection and talks to the Worker via `/api/sync/{state,snapshot,apply,peers}` (`server/sync.ts`).
  - `client/sync/signal.ts`: compact signals `S2~…` (~105 chars, ≤140 for ggwave). Fields are extracted from the local SDP (never munged) and the remote SDP is rebuilt from a template; «.» marks base64url-packed hex/mDNS.
  - `rtc.ts`: offer/answer, SAS code from both DTLS fingerprints. The mic is requested **before** creating the offer so Chrome exposes real host IPs instead of mDNS.
  - `protocol.ts`: `SyncSession` (id → hello → HMAC auth for remembered peers or a 4-digit confirm on both sides → `decide()` → 64 KB chunks + sha256 → apply with `pre-sync` backup → remember/markSynced). On a conflict the initiator fixes the winner (`decided`).
  - `components/sync/Pairing.svelte`, shared with `/lab/red-local`: it hands the open connection to its caller, and its cleanup must not close it.
  - Remembered peers live in internal `_syncPeers`; `_deviceId` likewise.
  - `buildSnapshot` must stay deterministic (`orderBy` on every select): «changed» is hash-based.
  - Tests: `tests/sync.test.ts` runs two real DBs over an in-memory transport. E2E: two headless Edge profiles + fake media, paste path.
- **Lab pages** `/lab/*` render without the Worker/dictionary (layout bypass). `/lab/ultrasonido`: experiment for pairing by sound (ggwave, lazy-loaded; `client/sound.ts`, types in `client/ggwave.d.ts`): tone/sweep audibility test, emitter, mic receiver (processing disabled) with 17-21 kHz meter. Plan: `docs/sync-qr.md`.
- **PWA**: `static/manifest.webmanifest` + icons (vermilion hanko seal with 先生 drawn from KanjiVG strokes: `icons/icon.svg` app, `icons/icon-maskable.svg` full-bleed safe zone, `favicon.svg` = 先 only for 16-32 px tabs; PNGs 192/512/maskable/apple-touch rendered from the SVGs with headless Edge — regenerate them if the SVGs change), `src/service-worker.ts` (Kit 3: `$app/manifest` `immutable`/`assets`, `$app/env` `version`), registered manually in prod by `client/pwa.ts` (`serviceWorker.register: false`). Kit only lists the Worker entry, so `precacheWorkerGraph` crawls its chunks and `.wasm` refs at install. `dict/` is never cached (lives in OPFS after install); external origins (Gemini, fonts) pass through. Cache `sensei-<version>`; `sensei-kanjivg` is kept across versions.

A «shifted» match that equals a later stroke is an order error. Costos shows cache % and savings.
- **Pregenerated content**: `data/pregen.ts` (format, `applyPregen` only fills nulls, `collectGenerated`) + `gemini/pregen.ts` (`pregenerateBatch`, `aheadStatus`). Origin `pregen` in `kanji.mnemonic_source`, `sentence.es_source`, `similar_kanji.tip_source`, `component.name_source`, `component.explanation_source`, `vocab.glosses_es_source`: never exported, never wiped by «reiniciar generado». In-app: Datos → «Preparar por adelantado» (`/api/pregen`, batches of 8). `scripts/pregen.ts` also backfills component explanations for already processed kanji.
- **Explained components**: `component.explanation` (JSON `ComponentExplanation`: depicts/why/role/examples/hook) from `ensureComponentExplanations` (feature `component_explain`, pro; examples filtered to kanji that really contain it), generated for the lesson's components and in pregen batches (`componentsToExplain` skips components that are kanji: those are taught as kanji). `getComponentInfo` adds `fullForm` (`COMPONENT_FULL_FORM` in `import/radicals.ts`, 氵→水), `examples` (studied kanji first, with meaning/status) and `distractors` (near kanji without it, for «¿en cuál aparece?»). UI: `ComponentCard.svelte` (lesson + `/kanji/[symbol]`), `KanjiHighlight.svelte` colors the component's strokes via `componentStrokes` (`strokes.ts`: KanjiVG groups by `kvg:element`/`kvg:original`, root group ignored; ungrouped strokes like 丶 in 主 can't be highlighted). SVGs via `client/kanjivg.ts` (memoized fetch).

Without a key `/api/lesson` returns `missing` (`missingContent`) and the lesson page explains what is missing, with a link to Ajustes.

ChatView: 🎙 record, 🗣 hands-free (`SilenceDetector`), 🔊 `speakMixed` (es/ja voices). Reviews: 🎙 for reading answers (`recognizeJapanese`; vocab answered in kanji is accepted if it is exactly the word).

## Review answering (added 2026-10-19)

- **Options**: `buildReviewItem` always attaches `options` (except trace, っ/ー words) via `srs/options.ts` `optionsFor` (kanji: `similarTo` → `confusion` → `learn_order` ±40, studied first; vocab/sentence: words sharing a kanji, then studied vocab; component: near `learn_order`; kana reading: romaji of `kanaCandidates`). `pick` drops any distractor that is itself valid (`meaningMatches`/`readingMatches` both ways) → no options if fewer than 3 safe ones. Kanji reading options are always hiragana. `kanaOptions`/`grammarOptions` live there too. `answerMode` stays the natural one; the client decides (setting `answerStyle`: `choice` (default) | `typed`, also toggled from the session bar and saved).
- **`review_log.via`** (`typed|choice|voice|trace`, null for old rows/other sources): `/api/answer` takes `via`; `applyReview` caps `choice` at Good (no Easy button either).
- **Voice** (`ReviewSession`, per-device `localStorage['sensei.review.voice']`): Web Speech `recognize(lang)` (`client/voice.ts`): `ja-JP` readings, `es-CL` meanings; only `kana`/`meaning` answer modes. `/api/grade` and `/api/answer` accept `alternatives[]` → `gradeSpoken` (correct if any alternative is; kanji output accepted if it equals the kanji/word/sentence target; `isGiveUp` «no sé»/«わからない» → `gaveUp`). Loop: speak prompt (meaning only, if `ttsEnabled`) → listen → 1 silence relistens, 2 → `voiceFallback` (options/typing) → correct: Good after 1.2 s; wrong: speak answer, Again after 2.5 s. ⏸ pauses. `seq` discards late results.
- **Fixed action bar**: `.bar` in `ReviewSession` is `position: fixed; bottom: var(--bottom-h)`, left/width measured from `.session`; one row only (secondary actions live in the reveal card). Layout publishes `--bottom-h` (mobile nav `offsetHeight`); the session publishes `--action-h`. Tutor FAB sits at `--bottom-h + --action-h` and shrinks to an edge tab while scrolling down (`TutorPanel.svelte`).
- Review shortcuts: 1-4 pick an option before answering; after, Enter / 1-2-3 grade. Ignored while typing in any input (tutor chat).

## Architecture

- `src/lib/server/db/` — schema + connection (see above). `openDb(':memory:')` from `db/bun.ts` for tests.
- `src/lib/server/import/` — build-time only (`scripts/build-dict.ts`): jmdict-simplified download (zip via fflate, `GITHUB_TOKEN` if set) → SQLite. `radicals.ts` maps RADKFILE substitute kanji (乞→𠂉, 个→𠆢, 汁→氵…) and static Spanish radical names. `order.ts` computes the single learn sequence (components before kanji; component-that-is-a-kanji is taught as kanji).
- `src/lib/server/srs/` — `fsrs.ts` (ts-fsrs wrapper, JSON-serialized card), `service.ts` (grading, confusions, reviews, interleave), `lessons.ts` (daily quota, brake at 80/150 due, vocab unlock when all kanji meaning cards are in Review).
- `src/lib/server/gemini/` — `client.ts` (models from settings override or defaults in `config.ts`), `enrich.ts` (cached mnemonics, component names, Spanish glosses/sentences), `texts.ts` (graded reading + explainer as token JSON, validated against JMdict), `tools.ts` + `tutor.ts` (chat loop).
- `src/lib/server/data/` — `snapshot.ts` (user-data .zip, `FORMAT` versioned: manifest + progress/tutor/generated/settings/content JSON; never includes `_`-prefixed internal settings). Export options: `SECTIONS` (progress incl. user vocab, tutor, library, usage, settings, content); a partial export is `FORMAT_PARTIAL` (2) with `manifest.sections`, so older apps reject it instead of wiping what it lacks; a full one stays format 1. Optional `device.json` (page `localStorage` prefs from `client/devicePrefs.ts`, applied by the page; only `sensei.*` keys) and `secret.json` (Gemini key sealed by `data/secret.ts`: PBKDF2-SHA256 600k + AES-GCM). `applySnapshot(db, snap, sections)` replaces only the chosen sections. `restoreFromZip` preview has per-section counts, `device`, `hasKey`; `keyPassword` is verified before anything is replaced. Backups and sync never carry device prefs or the key. `kanji.mnemonic_source = 'personal'` (`regenerateMnemonic`, uses learner notes) is exported with its source but never collected into pregen; `restore.ts` (import/restore = replace, always `pre-*` backup first), `backups.ts` (BlobStore, daily auto skipped if empty or hash unchanged, 7-day retention keeping newest, hourly scheduler started by the Worker), `reset.ts` (progress all/groups/item, tutor, generated; "kanji" group cascades components+vocab).
- `src/lib/server/guide.ts` — `nextSteps` (prioritized "what now + why": welcome → kana → report → reviews → leeches → lessons → reread → speed → reading → goal → confusions → tutor → library), `goalStatus`, `journey`/`MILESTONES`. `/` redirects to `/bienvenida` when `onboardingDone` is false and there are no cards.
- `src/lib/grammar.ts` — curated grammar track (`GRAMMAR`, ids stable: they are card keys). Meanings must stay unique (used as multiple-choice distractors; tested).
- `src/lib/deinflect.ts` — rule-based deinflector (Yomichan-style, type flags). `lookupInflected` (items.ts) validates candidates by JMdict POS.
- `src/lib/server/text/` — `analyze.ts` (offline tokenizer: longest match ≤14 chars against `vocab_form` + deinflection; coverage + study plan), `library.ts` (txt/srt/epub import, reading log, reread intervals `REREAD_DAYS`, speed), `sentences.ts` (mined sentence cards, offline speed text from Tatoeba).
- `src/lib/server/srs/` additions — `optimizer.ts` (fsrs-rs via `@open-spaced-repetition/binding`, aliased to fsrs-browser WASM in the site: `computeParameters`, workload compare, replay history to reschedule; skips placement cards), `placement.ts` (level test; cards created with `createdAt` in the past so they don't consume today's quota), `lessons.ts` (study queue first: queued kanji with their missing components; queued vocab ignores unlock; grammar lessons).
- `src/lib/server/report.ts` — weekly metrics (retention = review answers with previous answer ≥1 day earlier) + Gemini/fallback text; appended to learner notes.
- New item types: `grammar` (facet meaning, answerMode `choice`) and `sentence` (key = mined_sentence.id, facet reading). `LEECH_LAPSES = 6` (FSRS lapses only count failures from Review state).
- `src/lib/server/gemini/pricing.ts` + `usage.ts` — cost tracking. `DEFAULT_PRICES` (USD/1M, dated tiers `from`, prefix match via `priceKey`), overridable per model by setting `modelPrices`. `recordUsage` writes one `gemini_usage` row per call (cost frozen at call time; `recomputeCosts` rewrites history). `costReport`/`budgetStatus`/`sessionCosts` feed `/costos`, Inicio and the sessions table. `trackCost(fn)` (AsyncLocalStorage) sums nested calls of one operation → `cost` in reading/explain/report responses (`CostNote.svelte`). `priceKey` prefix match only with a version suffix (`-preview|-latest|-exp|-customtools|-<digit>`), so `…-flash-tts` doesn't inherit `…-flash`. Tiers may carry `long` (prompt > 200k).
- Model picker: `GET /api/models` = `listModels()` (10-min cache, `isCompatibleModel` filter) + `priceSummary` + per role `usd` = last-30-day calls of that role (`FEATURE_ROLE` in usage.ts — keep in sync with `models(db).pro/.flash` callers) repriced with the candidate (`projectCost`; `mixCost` 90/10 if no usage). `ModelPicker.svelte` computes «Relativo» against the form's current value.
- Client: `src/lib/client/` (api/SSE, backend bridge, base path, markdown+furigana renderer, TTS, rune state), `src/lib/components/`.

## Kana course (learning from zero)

- Content is fixed and hand-curated in `src/lib/kanaCourse.ts`: `KANA_ROWS` (teaching order: hiragana basic → dakuten → yōon → っ, then katakana same + ー + extended), Spanish mnemonics for the 92 basic kana, example words (kana only, tested), `KANA_SIMILAR` tips, `KANA_RULES` per group, `SPECIAL_WORDS` (っ/ッ/ー are practiced with whole words). `kana.ts`: `acceptedRomaji` (yōon/extended alternatives), `wordRomaji` (ー lengthens, っ doubles, macrons, を→o, Kunrei).
- Server `server/kana.ts`: `nextKana` (whole rows up to `newKanaPerDay`), `hiraganaReady` = 46 basic hiragana have reading cards (or any kanji card) — until then `lessonQuota` sets `kanjiLocked` (kanjiLeft = grammarLeft = 0) and `nextLesson` serves `{type:'kana'}` items first. `knownCard` = Review card with stability 30, createdAt in the past. `legacyKnownKana`: users from before the course (diagnostic/placement logs or kanji cards, no kana lesson logs, no `startLevel`, no `kanaAssessed`) count the old diagnostic set as known — **computed, never written** (writing cards on open/import broke sync hashes). `weakKanaChars` → layout `weakKana` → `prefs.weakKana` → `KanaHint.svelte` (small romaji under kana readings only while some char is not solid).
- Kana facets: `reading` (kana → romaji; specials show an example word), `meaning` = inverse (romaji + 🔊 → choose among `kanaOptions`, similar first), `writing` (trace, opt-in with `writingReviews`; kana go first in `ensureWritingCards`). `facetsFor(type, key)`.
- Welcome step «Tu punto de partida» stores setting `startLevel`; «empezar» goes to `/kana?diag=…` (adaptive `KanaDiagnostic.svelte`: ~15-item sample per script, 6 fails → `skipped`, else the rest; API creates known cards for correct+fast and calls `markKanaAssessed`) or to the first kana lesson. `/kana` = progress, diagnostic, `KanaPractice` (`/api/kana/words`: common kana-only words using taught kana) and the map. Guide steps `kana`/`kana-lesson`/`kana-practice`, milestones `hira`/`kata` (`kana`, `badge`), daily «Lección de kana» and «Leer palabras en kana», tutor state carries the kana level (romaji in parentheses allowed only while a script is being learned).

## Invariants / gotchas

- **AI mode** (setting `aiMode`: `ask` | `on` | `off`, travels in copies/sync): `hasGemini()` = key && `!config.aiOff`; `config.aiOff` is kept by `syncAiMode(db)` (worker open, dictionary update, `restoreFromZip`, `updateSettings`/`resetSettings`). Saving a key sets `on`; turning AI off keeps the key. Layout data: `aiMode`, `aiKey`, `aiUi` (= `on` or `ask` with a key). Client: `client/ai.svelte.ts` (`aiUi()`, `aiMode()`, `setAiMode`). Without `aiUi`: nav items marked `ai` (tutor, lectura, explicar, costos) are hidden, those routes render `AiOff.svelte`, no `TutorPanel`, `askTutor` is a no-op, and «¿Por qué?», «Preguntar al tutor», generate/regenerate buttons, PregenPanel, the Inicio tutor card, the key/model cards in Ajustes and the AI sections of the guide are hidden. `ask` without a key shows `AiChoice.svelte` (top of the layout, and the «La IA» step of the welcome) instead of a warning. The mode is shown at the foot of the sidebar/«Más», on Inicio and in Ajustes `#ia`. New AI features must be gated with `aiUi()` (UI) and `hasGemini()` (server). The Ajustes form must not post `aiMode`. Wherever the AI choice is offered (welcome, top card, Ajustes), «Sin IA» goes first and highlighted; in the welcome it is preselected (saved only on «Siguiente»). Going from off/ask to on (any of the 4 entry points) shows the «Lo que añade la IA» dialog; in the welcome, after the Gemini step.

- **Notifications = toasts** (`client/toast.svelte.ts` + `components/Toaster.svelte`, mounted once at the layout root, top-center, z 70): `toast.success|info|warn|error(msg, { detail, duration, actions, key, persistent })`. Defaults: success 3.5 s, info 5 s, warn 8 s, error stays until closed; hover/focus pauses; `key` replaces a previous toast (net status, version, daily). `show` runs in `untrack`, so calling it from a `$effect` is safe. Swiping a toast left, right or up dismisses it (pointer events: touch and mouse), except `persistent` ones. A failed dictionary update reports `updateError` in the ready state → error toast. Use them for action confirmations and transient failures; keep inline only errors that replace a page's main content or belong to a form field. Don't add new `msg`/`setTimeout` banners.

- **Tutor tools** (`gemini/tools.ts` + `gemini/actions.ts`):
  - Queries return data.
  - UI tools return a `UiBlock` (`card`, `choices`, `links` from the `DESTINATIONS` whitelist, `jptext`).
  - Actions live in the `ACTIONS` registry. `direct` actions run immediately and store an `undo` payload in `tutor_action`. `confirm` actions only store `proposed`; `/api/tutor/actions/[id]` confirms, rejects or undoes them.
  - Outcomes reach the model on its next turn via `pendingReports` (`[Sistema: …]`).
  - Never add global-destructive tools (reset all, import/restore, backups, delete sessions); `tests/tutor-actions.test.ts` guards this.
  - New sensitive actions must be `confirm`.
- Screen context: pages call `setScreenContext` (`client/tutorContext.svelte.ts`). The layout clears it on navigation. The panel (`chat/TutorPanel.svelte`) attaches it as `[Contexto de pantalla: …]` plus a `context` UI chip.
- Sessions are created lazily by `POST /api/chat/start` (first SSE event `{type:'session'}`); `/tutor?nuevo=X` redirects to the draft page `/tutor/nueva?modo=X`. `title_source`: auto | summary | user (user titles are never overwritten). Panel continues the last `origin='panel'` session active < 3 h. New messages reset `summarized`.
- `ChatView.svelte` is shared by `/tutor/[id]`, `/tutor/nueva` and the panel. Any URL with `?tutor=1` opens the panel (also handy for headless screenshots).
- Gemini transient errors (429/500/503): `withRetry` for one-shot calls; the tutor loop retries the stream before any chunk arrives. If a turn still fails, `turnIncomplete` is true and the UI offers «Reintentar» (`{retry:true}` continues the model loop without a new user message). `errorMessage` maps HTTP codes to Spanish messages.
- UI check: Edge headless works on Windows (`msedge --headless=new --user-data-dir=<unique> --window-size=W,H --screenshot=<win path> URL`); width < ~500 px gets clipped, use 500 for mobile. A fresh profile starts at the «descargar diccionario» screen; drive it via DevTools (`--remote-debugging-port`) to click install. Kill headless Edge afterwards or its Web Lock blocks the next run.
- **Tutor history stores raw Gemini parts** (`message.parts`) including `thoughtSignature`; never rewrite them (only `compactParts` merges plain text parts).
- `present_quiz` ends the model turn. Its `functionResponse` is sent with the learner's next input; responses to other calls made in the same turn are held in a hidden `{type:'pending'}` UI block and sent together. Every functionCall must get a response in the next user content.
- Furigana notation in tutor text: `{漢字|かんじ}`; rendered by `client/markdown.ts` (stray `{x}` without pipe is shown as `x`; ordered lists keep numbering across blank lines/sublists — tests in `tests/markdown.test.ts`). Adaptive mode hides it when every kanji in the word has a reading card in Review with stability ≥ 7 days (`readableKanji`).
- Item statuses: none / learning / review / mastered (stability ≥ 21 d), worst facet wins.
- Card keys: kana char, component symbol, kanji char, vocab id (`jm:<id>` from JMdict, `u:<uuid>` user-created).
- Theme: light/dark/system per device (`localStorage['sensei.theme']`, absent = system). `app.html` inline script sets `data-theme` before paint; `client/theme.svelte.ts` cycles it. All colors are CSS vars in `app.css` (light block duplicated for `[data-theme=light]` and `prefers-color-scheme`); don't hardcode colors in components except white text on colored fills.
- Charts follow the dataviz skill via vars: `--series-1` (dark `#3987e5`, light `#2a78d6`) and ordinal `--ord-1..3` + `--ord-N-ink` for learning/review/mastered (dark `#1c5cab/#3987e5/#86b6ef`, light `#86b6ef/#2a78d6/#184f95`).
- Provenance columns: `vocab.glosses_es_source` (jmdict|gemini|user) and `component.name_source` (static|kanji|gemini), `component.explanation_source` (gemini|pregen). Set them whenever writing those fields: export and "reset generated content" depend on them.
- New user tables must be added to `Snapshot` (export/import), `applySnapshot` (replace) and, if they are progress, `reset.ts`. Bump `FORMAT` only for incompatible changes; new snapshot fields are optional (`?`) so older zips still import.
- FSRS scheduler is built per call from settings (`schedulerConfig(db)`: custom params + desired retention), memoized in `fsrs.ts`.
- Review prompt fonts are chosen client-side (`pickFont`, Google Fonts loaded only if `fontVariety`); kana/components/grammar always gothic.
- **Every Gemini call must be tracked**: `generateJson`/`generateText` require `db` + `feature` (key of `FEATURES` in `usage.ts`; keys are stored, don't rename); the tutor stream calls `recordUsage` itself with the last chunk's `usageMetadata`. Failed calls are rows with `ok=false`, cost 0. Unknown model → `cost_usd` null («sin precio»). Deleting a session keeps its usage rows.
- Settings form in /ajustes must not post `goal`/`fsrsParams`/`modelPrices`/`monthlyBudgetUsd`/`budgetHardStop`/`aiMode`/`startLevel`/`kanaAssessed` (they have their own actions; prices, budget and hard stop go through `POST /api/costs`).
- SQLite LIKE treats `_` as wildcard: use `substr(key,1,1) != '_'` for internal settings, not `like '\_%'`.
- **Never `db.get(sql\`…\`)`** with raw SQL: bun-sqlite returns an array of values (`[2600]`), not an object. Use `one<T>(sql\`…\`)` from `#lib/server/db/index.ts` (or `db.all(...)`). Query-builder `.get()` (`db.select()...get()`) is fine.
- The API only exists inside the browser now: test it from page context (DevTools `Runtime.evaluate` → `fetch('/api/…')`), not with curl.
